# 0.1.5.4

## Major Changes

- Added support for Paper 26.3.
- All saving now runs on a single `TNE-Storage` thread. Autosaves no longer overlap or create new
  Craft Scheduler threads, and the server no longer waits 10 seconds for TNE when stopping.
- Reworked Redis cross-server sync. **Every server must run 0.1.5.4; older versions cannot exchange
  sync messages with it.**
  - Servers now send balance changes instead of resulting balances, so changes made on several
    servers at the same time all count. Previously over half of them could be lost.
  - Sync uses a Redis stream (`tne:sync`) and reconnects automatically; changes made while Redis or
    a server's connection was down are delivered once it is back. Previously sync stopped for good
    after a Redis restart.
  - Cross-server player notifications are delivered again.
  - TNE warns when two servers share the same `Core.ServerID`, e.g. after copying a server folder.

## Fixes

- Fixed the server crashing (`NoClassDefFoundError` in `net.tnemc.libs.lamp`) when a player tab
  completed a TNE command after TNE had been disabled, e.g. because it failed to start. TNE now
  removes its commands when it is disabled.
- Fixed TNE failing to enable on Paper 26.3 (`NoSuchFieldError: MAP_COLOR`).
- Fixed decorated pot items failing to convert (`No conversion registered from String to Material`).
- Fixed errors when using items with an inline (unregistered) value, such as a goat horn with a custom
  instrument (`Cannot get key for this registry item, because it is not registered`).
- Fixed balance changes being lost when plugins used Vault from several threads at once.
- Fixed `/tne reload`, `/tne reloaddb` and `Data.Sync.Reload` discarding balance changes that had
  not been saved yet.
- Fixed changes made during an autosave being skipped by later saves, and failed saves not being
  retried.
- Reloads (`/tne reload`, `/tne reloaddb`, `Data.Sync.Reload`) are now cancelled when unsaved
  balances cannot be saved, e.g. while the database is down, instead of wiping in-memory balances.
- One account or transaction receipt that fails to save no longer stops the others from saving.
- Fixed item currency balances of online players not being saved on shutdown.
- Fixed a failed YAML save blocking every later save of that account.
- Fixed `/transactions` showing nothing after a restart, payments missing from the recipient's
  history, and transactions made within the same second being merged into one entry. History now
  shows the newest transactions first, and the initiator shows the player or plugin (e.g. Vault)
  when there is no paying account.
- Fixed players without `tne.transaction.history.other` being able to view other players'
  transaction history with `/transactions <page> <region> <player>`.
- Fixed Vault's name-based `createPlayerAccount` replacing an existing player's account with an
  empty one, and reading every player data file to look up unknown names.
- Item currency balances are no longer read from player inventories outside the server thread
  (autosaves, balance top refreshes, async PlaceholderAPI and Vault balance checks). These use the
  balance copied from the inventory at the last autosave, `/tne save` or logout.
- Fixed a player's item balance being taken from storage instead of their inventory for the rest of
  their session after an error while joining.
- Account name tab completion lists offline accounts only once a name is being typed, at most 50.
- Receipt tables are updated automatically on MySQL and MariaDB so every participant of a
  transaction is stored.

Receipts saved before this version only kept their first participant; the missing details cannot
be recovered. Balances already lost to the bugs above need to be corrected manually.
